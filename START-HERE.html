이번 버전: 세 사람의 공정 분담

A는 점검·분해·세척 후 B 대기함으로 전달, B는 교체·조립·복원·검사, C는 응대·매입·판매·진열·정리를 맡습니다. A와 B는 서로 다른 물건을 동시에 작업합니다.

기존 SQL은 동일합니다. 이미 실행했다면 1단계는 건너뛰세요. 기존 config.js 접속 정보는 유지하고 전원 같은 0.5.6 파일을 사용하세요.

이미 만든 Supabase 프로젝트와 GitHub 저장소를 사용합니다. 가입은 다시 하지 않습니다.
이 파일은 설명과 SQL 복사만 제공하며 서버에 접속하거나 설정을 실행하지 않습니다.

1. 기존 Supabase에 추가 SQL 실행

  1. 기존 프로젝트를 열고 왼쪽 SQL Editor → 새 쿼리를 선택합니다.
  2. 아래 SQL 전체를 복사해 붙여넣고 Run을 누릅니다.
  3. Success / No rows returned가 나오면 다음 단계로 갑니다. 오류가 나면 문구와 줄 번호를 확인합니다.

예전 SQL과 테이블은 삭제하지 않습니다. 이번 코드는 새 cr5_ 테이블·함수를 추가합니다.

2. 기존 공개 접속 정보 입력

  1. Supabase 프로젝트의 Connect에서 Project URL과 publishable key를 확인합니다. 키 목록은 Settings → API Keys에서도 확인할 수 있습니다.
  2. 압축을 푼 폴더의 config.js를 메모장으로 열어 두 빈칸에 넣고 저장합니다.
window.SHOP_CONFIG = {
  supabaseUrl: '여기에 Project URL',
  supabaseAnonKey: '여기에 공개 publishable 또는 anon 키'
};

공개 키만 사용합니다. service_role·sb_secret_·DB 암호는 넣지 않습니다. 공개 접속 정보는 이번 산출물에 들어 있지 않습니다.

config.js를 수정하지 않고 각 기기의 게임 연결 설정에서 입력할 수도 있습니다.

3. 기존 GitHub 저장소에 업로드

kiesi10041-jpg/cozy-repair-cat → Add file → Upload files.

아래 파일과 폴더를 저장소 최상위에 올리고 Commit changes를 누릅니다.

config.js

ZIP 파일 자체만 올리지 마세요. index.html만 올려도 실행되지 않습니다. 폴더 구조를 유지해야 합니다.

Settings → Pages → Source: Deploy from a branch → main / (root) → Save.
이미 같은 설정이면 변경하지 않습니다. Pages에 표시된 실제 접속 주소를 사용합니다.

4. 세 명이 실제 연결 확인

  1. 각자 다른 기기 또는 별도 브라우저 프로필에서 게임 주소를 엽니다.
  2. 첫 사람: 3인 멀티 / 연결 설정 → 서버 연결 → 이름 → 새 공동 상점 만들기.
  3. 나머지 두 사람: 같은 화면에서 이름과 8자리 방 코드 → 참가.
  4. 세 명 모두 준비하기, 방장이 영업 시작.
  5. 공동머니·카운터 점유·수리 넘기기·재접속을 확인합니다.

같은 브라우저의 탭 3개는 동일한 익명 로그인 신원을 공유할 수 있습니다. 익명 신원은 브라우저 데이터 삭제나 다른 기기로 자동 이전되지 않습니다.

검증 범위와 남은 부분

물건 이미지·수리·진열·저장 이어하기는 브라우저에서 확인했습니다. 3인 공동 상태·재시도·방장 인계는 모의 연결 검사까지 통과했습니다.

실제 Supabase SQL·RLS·3기기 멀티 검증은 아직 하지 않았습니다. 배경 확장·두 번째 작업대 원화·고양이/말 NPC 원화·품목별 상급 퍼즐은 후속 작업입니다. 자세한 상태는 README.md와 DEVELOPMENT.md에 있습니다.
