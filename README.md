# 개발판 0.5.8 — 3인칭 진열용 도트

가게 배경을 기준으로 새로 생성한 8종 진열용 아틀라스를 추가했습니다. 거래용 정면 그림을 축소해 쓰던 지도와 진열 화면은 이제 위에서 내려다본 별도 물품 그림을 공유합니다. 32×32 논리 타일에 품목별 크기를 맞추고 배경과 같은 픽셀 단위로 렌더링합니다. 플레이어는 36×48 논리 픽셀로 정규화해 NPC와 픽셀 밀도를 맞췄습니다. 6칸 확장 진열대도 실제 여섯 칸으로 표시합니다.

거래·수리 화면의 상세 원화는 기존 자산을 유지합니다. 원화 전체를 다시 그린 업데이트는 아닙니다. config.js는 기존 연결값을 유지하고 SQL은 다시 실행하지 않습니다. 기존 저장 데이터를 그대로 이어서 사용할 수 있습니다.

테스트 렌더링: tests/world-art-preview.png (8종을 4개씩), tests/world-art-six-preview.png (확장 6칸). 이미지 생성 기준과 프롬프트는 WORLD-ART.md에 기록했습니다.

# 개발판 0.5.8 변경 사항

- 판매가는 1원 이상의 정수로 자유 설정합니다. 기준가 비율 상한과 브라우저 팝업 경고를 제거했습니다.
- 높은 가격표에 대해 손님은 물품 가치와 성향별 구매 한도를 기준으로 거절합니다. 과도하게 비싼 가격표는 판매 확정을 막고 낮은 금액의 재제안을 받습니다. 플레이어가 손님의 역제안에 동의하면 그 금액으로 거래할 수 있습니다.
- 거래 화면의 성향·대사 잘림, 가격 입력줄 배치, 관련 없는 이전 알림을 수정했습니다.
- 판매 물품 선택 드롭다운이 Enter 입력 없이도 즉시 동작하도록 수정했습니다.
- 지도 카운터 담당은 정면으로 보이게 하고 상체와 테이블의 겹침 위치를 맞췄습니다. 이동 좌표나 길찾기는 바꾸지 않았습니다.

기존 config.js 연결값은 유지하세요. SQL 재실행은 필요 없습니다. 원화 화풍 통일은 이 수정 범위에 포함되지 않습니다.

# 우리의 작은 수리점 · 개발판 0.5.8

## 이번 수정
- 손님·물건·테이블이 같은 거래 장면에 보이도록 구성했습니다. 손님은 테이블 뒤, 물품은 앞쪽 상판에 닿도록 합성합니다.
- 지도·진열 확대에서 물품의 투명 여백이 아닌 실제 바닥을 기준으로 위치를 맞춥니다. 진열 테이블과 물품을 같은 픽셀 배율로 확대합니다.
- 수리 화면의 과도한 확대를 제한하고 기존 원화와 색감을 유지합니다. 원본 이미지를 고해상도 원화로 복원했다는 뜻은 아닙니다.
- 완료품은 판매가를 먼저 저장해야 진열할 수 있습니다. 가격표와 손님 제안은 저장 판매가를 사용하며 기준가는 별도로 유지합니다.
- 판매가 범위는 기준가의 65~145%이며 기존 진열품의 가격 변경도 지원합니다. 이미 진열된 옛 저장품은 기존 기준가를 판매가로 이어받습니다.
- 흥정은 성향에 따라 5~6회 진행합니다. 손님의 양보 한계가 라운드마다 변하며 내 입력 금액은 손님 역제안으로 덮어쓰지 않습니다.
- 거래 확정 전에는 합의 후에도 추가 흥정할 수 있습니다. 무리한 제안을 반복하면 손님이 거래를 끝낼 수 있습니다.
- 지도에서 카운터 안쪽 캐릭터의 상체가 가려지던 높이를 조정했습니다. 분해·복원 지도 라벨은 계속 표시하지 않습니다.

## 아이폰 실행
1. GitHub Pages에 전체 파일을 올립니다. 기존 config.js의 공개 접속 정보는 유지하세요.
2. Safari에서 게임 주소를 열고 공유/더보기 → 홈 화면에 추가를 선택합니다. 웹 앱으로 열기가 표시되면 켭니다.
3. 홈 화면 아이콘으로 실행하고 기기를 가로로 돌립니다. 방 참가도 이 아이콘에서 시작하세요.
4. 가게 / 창고 / 운영 / 설정 탭으로 전환합니다. 일반 Safari 탭에서 버튼만으로 주소창을 없애거나 가로 방향을 강제 고정하는 방식은 지원하지 않습니다.

- 진열품의 고유 번호·상태·수리 담당·기준가를 확인하고, 선택 진열품을 회수하거나 다른 칸으로 이동·교환할 수 있습니다.
- 빈칸 일괄 진열과 보관함 정리를 지원합니다. 판매는 기존 카운터 흥정·거래 확정 흐름을 사용합니다.
- 지도 위 물건 좌표를 실제 테이블의 칸 중앙에 맞췄습니다. A 작업대 앞·B 작업대 측면·C 진열 테이블 앞 이동 지점을 더 가깝게 맞췄습니다.
- 업그레이드한 테이블은 6구역으로 나누어 사용합니다. 기존 저장의 진열 순서와 물품 ID를 보존합니다.
- 여러 동료의 요청이 겹치면 물품·칸 상태를 재검사하여 중복 진열이나 덮어쓰기를 막습니다.

## 이전 변경: 물품 선택·부품 확인·작업대 크기 안정화
- 완료 화면도 작업 중과 동일한 344×344 표시 영역을 사용합니다. 상태별 이미지는 고정된 아틀라스 셀에서 읽습니다.
- A 매입함과 B 대기함을 물품 이미지·고유 번호·손상·가격·필요 부품·공동 재고가 있는 카드로 표시합니다.
- A→B 인계 시 같은 물건 번호와 점검·담당 기록을 유지합니다. B가 원하지 않은 첫 물건을 자동 인수하지 않습니다.
- A 인계 준비와 B 교체·복원은 같은 분해 이미지를 사용합니다. 완료 때 크기를 축소하지 않습니다.
- B의 재료 부족은 인수 전에 안내하며 배송 중·도착·수령 상태를 구분합니다. 트레이에도 실제 재고를 표시하고 0개 재료는 선택을 막습니다.
- 새 물건·공정에 들어갈 때 드래그·선택 부품·문지르기 진행을 초기화합니다. 인수 확인 중에는 지난 완료품을 보여주지 않습니다.
- 수리 화면에 조명·벽 도구판·나무 작업대·녹색 매트 배경을 추가했습니다. 가게 지도와 기존 캐릭터 이미지는 유지합니다.

## A/B 작업 + C 운영을 동시에
A와 B는 별도 물건·진행·소유권을 갖습니다. A가 다음 물건을 분해하는 동안 B는 앞서 받은 물건을 복원하고 C는 응대와 진열을 진행합니다.
배경을 지우거나 바닥을 덮지 않았습니다. 기존 작업대 앞은 A, 오른쪽은 B의 상호작용 위치입니다. 별도 두 번째 작업대 원화는 아직 추가하지 않았습니다.

| 기본 담당 | 작업 | 다음 담당에게 전달 |
|---|---|---|
| A | 물건별 손상 3곳 점검 → 나사 분해 또는 표면 세척 | B 대기함으로 전달 버튼 |
| B | 중간함 인수 → 재료 드래그 교체 → 부품별 방향 조립 또는 표면 복원 → 최종 검사 | C 진열 대기에 자동 보관 |
| C | 손님 응대·매입·흥정·판매·완료품 일괄 진열·물건 정리·부품 주문·택배 수령 | 새 매입품을 A에게, 재료를 B에게 공급 |

기본 담당은 A/B/C 캐릭터에 표시됩니다. 한 사람이 A와 B를 동시에 독점할 수 없습니다.
현재 공정 내려놓기를 누르면 진행은 유지한 채 다른 동료가 인수할 수 있습니다.
C도 응대를 마친 뒤 비어 있는 공정을 도울 수 있습니다. 공정 점유 중에는 카운터를 함께 점유할 수 없습니다.

## A공정
1. 물건 위의 돋보기 세 곳을 눌러 고장 부위를 확인합니다. 물건마다 점검 항목이 다릅니다.
2. 기계는 번호 순서대로 나사를 반시계 방향으로 돌립니다. 주전자·그림·의자는 오염 영역을 문질러 정리합니다.
3. B 대기함으로 전달을 누릅니다. 분해한 물건·점검 기록·A 담당 기록이 넘어갑니다.
4. A는 곧바로 다음 고장품을 시작할 수 있습니다. 중간 보관함은 최대 6개입니다.

## B공정
1. B공정 버튼을 누르면 중간 보관함의 이미지·물건 번호·A 담당·필요 부품을 확인하고 원하는 물건을 직접 인수합니다. 부품이 없으면 먼저 주문·수령합니다.
2. 필요한 재료를 트레이에서 빛나는 위치로 끌어 놓습니다. 틀린 재료에는 재고를 쓰지 않습니다.
3. 시계·라디오·음악상자·카메라·축음기는 품목별 부품명과 목표 방향에 맞춰 조립합니다.
4. 주전자·그림·의자는 손상 영역을 붓으로 문질러 복원합니다.
5. 물건 위 스위치 또는 돋보기로 검사합니다. 완료품은 C의 진열 대기 목록에 표시됩니다.

## C 운영과 작업 현황
- 완료품 일괄 진열: 빈 진열칸만큼 완료품을 배치합니다.
- 물건 정리: 매입함은 손상이 큰 순서, B 대기함과 완료함은 기준가 높은 순서로 정렬합니다.
- 다음 할 일에는 도착 택배·B 재료 부족·진열품·손님 응대 등을 표시합니다.
- 현황판에서 A/B 물건과 담당자, 중간함, 완료함, 카운터 점유와 인계 기록을 확인합니다.
- 새 오프라인 게임에는 매입품 2개와 전날 A공정을 마친 주전자 1개가 있어 세 역할을 바로 시험할 수 있습니다.
- 기존 저장을 불러올 때는 이 초기 물건을 다시 지급하지 않습니다.

## 저장과 이어하기
A/B 공정·담당자·점검·회전 분량·완료 영역·재료 소비·중간함·완료함을 함께 저장합니다.

마감 시 공정을 취소하지 않고 진행을 보관하며 다음 날 그대로 이어갑니다.
브라우저 자동 저장과 JSON 저장 파일을 유지합니다. 온라인은 서버 스냅샷을 사용합니다.
익명 참가자 신원은 같은 브라우저의 로그인 저장에 의존합니다. 이메일 연결·자리 복구는 아직 미구현입니다.

## 검증
- 브라우저: A 점검·분해→B 전달·인수→B 작업 유지 중 C 매입→A 다음 물건 시작→C 응대 병행.
- 도메인: 8종의 A→B→C 이동, 소유권 충돌 방지, 공정 넘기기, 동시 저장/복원, 마감 보존, 이전 저장 변환.
- 입력 이벤트: 8종의 원형 회전·드래그·문지르기·검사.
- 3클라이언트 모형: 두 공정+응대 동시 유지, 공동머니, 저장 전/후 통신 실패 재시도, 방장 인계, 오프라인 담당자 작업 보존.
- 실제 Supabase SQL/RLS·실시간 채널·3기기 멀티 및 휴대폰 터치는 아직 검증하지 않았습니다.

## 유지·후속 범위
원래 배경·캐릭터 125개, 골동품 8종×3상태 이미지, 가격 흥정·성장·광고·장비·저장·핑·효과음을 유지합니다.
고양이/말 NPC 추가 원화, 점포 외형 확장, 별도 작업대 원화, 더 다양한 품목 전용 퍼즐·상급 난이도, 이메일 신원 복구는 후속 과제입니다.
멀티는 친구끼리 운영하는 방장 권한 모델입니다. DB는 멤버십·버전·명령 식별·저장을 보호하며 공개 경쟁용 서버 규칙 검증은 미구현입니다.
